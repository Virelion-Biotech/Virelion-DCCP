# DCCP 0.4.0 CPU audit

## What is verified

DCCP's minimal installation, scenario validation/auditing, label-blind defensive
assessment, host count normalization, marker summaries, challenge materialization,
recovery arithmetic, release/integrity gates and optional CardiVex/CardiSim adapters
are exercised on CPU. No GPU is needed. These checks do not establish biological,
clinical or calibrated OOD validity.

Baseline commit: `95f732e7f9c728cae681fe47dc550c62e2630bbe`.
The documented minimal installation failed test collection because CardiVex was
unconditionally imported despite being optional. With CardiVex supplied, the
baseline had 75 passing tests. Seven further defects were reproduced before repair:
OOD label leakage, ignored abnormality radius, missing coverage interpreted as
absence, ignored unknown axes, overflowed count normalization, unchecked manifest
digests and unbounded recovery inputs.

## Scientific and real-input evidence

The complete public GSE240848 MatrixMarket file was downloaded and streamed:
32,623 rows, 48,637 columns and 62,845,195 coordinate records. Annotation dimensions,
coordinates and count signs were checked. The frozen technical subset contains the
first 16 columns, 54 available marker symbols and one aggregate non-module row.
Duplicate marker symbols are summed. Pooling all remaining gene counts preserves
each selected cell's complete library total. This is not a representative cohort;
there is no donor/condition assignment and no MI-versus-control inference.

`validation/data/GSE240848_host_subset.json` records URLs, SHA-256 and byte lengths
for the exact three source files. The 235 MB compressed matrix is not redistributed.
`python scripts/fetch_host_subset.py` reproduces the subset and rejects source hash
drift. Downloaded files stay outside version control. The small derivative fixture
supports offline CI; it is explicitly identified as a technical test subset.

## Detector results, including failures

Eight pre-existing scenario design labels were evaluated without using them as
prediction inputs. No thresholds were selected from these results.

| Detector | OOD agreement with design flags |
|---|---|
| Heuristic | 3/8, 37.5% |
| Prototype | 7/8, 87.5% |

These are small synthetic diagnostic results, not generalization estimates.
The report includes confusion matrices, case-level failures and Wilson intervals.
All eight scenarios are abnormal designs, so this set cannot estimate healthy-case
specificity. Design-held-out flags are not independently measured OOD ground truth.
SCENARIO-017 remains a genuine heuristic miss after removing label leakage; its
regression now checks the distance-based decision rather than requiring the answer
encoded in metadata. Empirical validation is explicitly `not_validated`.

## Scientific contract repairs

- `ood_flag` may define a training exclusion/design label but never a prediction.
  The configured prototype abnormality radius now controls its decision in raw
  ordinal-vector Euclidean units. Ordinal values are equally spaced heuristics.
- Missing scores/genes are unavailable (`null`), not evidence of a healthy state.
  Low-level module/hub helpers also return unavailable values when no markers
  are measured. Incomplete omics-derived drafts carry `unavailable_axes` and cannot silently enter
  detector assessment. Unknown axes and out-of-range scores fail.
- Raw host marker means and gene coverage are retained. Relative scores describe
  within-profile heterogeneity, with invariant profiles unavailable. They are not
  calibrated cross-sample burden. An absent gene list yields unknown coverage.
- Uncalibrated expression summaries no longer fabricate simulator phenotype states
  or viability. High contractile-gene abundance is not automatically dysfunction;
  mixed BAX/BCL2/CASP3/XIAP/MCL1 abundance is not a measured death fraction.
- Normalization actually uses CP10K, historically named `log1p_cpm_rows`; the public
  name is retained for compatibility. Compensated sums prevent overflow and order
  artifacts. Genes are case-normalized, not orthology-mapped.
- Recovery uses bounded [0,1] input states, common measured dimensions and only
  actually challenged dimensions for restoration fractions. Unaffected dimensions
  cannot inflate recovery. The health index remains an arbitrary model-dependent
  heuristic, not a validated physiological quantity.
- Wilson intervals with no observations span [0,1]. Duplicate evaluation IDs and
  non-boolean case labels fail; undefined metrics are identified explicitly.

## Artifact and product hygiene

Strict JSON rejects duplicate keys, NaN/Infinity and overflowed numbers. Scenario
construction validates and copies input mappings. Serialization occurs before
atomic replacement with unique temporary files, preserving existing artifacts on
failure. Bundle manifests are accepted by the integrity command; whole-manifest,
file digest, size and duplicate-path checks detect drift. External source paths
cannot create an unverifiable source manifest.

Release gates require actual boolean audit success and, when files are supplied,
re-audit content and scenario identity rather than trusting a registry assertion.
Counts, hashes and path containment are checked. Challenge IDs must be unique;
empty or policy-failed sets cannot be materialized. Schema/panel/example copies
inside the wheel match repository sources. Bundled examples make `dccp list` and
materialization work outside a checkout.

CardiVex is optional at runtime; the pure-Python fallback has the same bounded
ordinal semantics. Optional adapters are pinned to CardiVex
`47b9097b4ee869e7fafe56daaa0436fa7ef556de` and CardiSim
`b42e3ba1c9141f762be1d1bf3cb2df68e97baab2`. External simulator output must be finite
JSON and integer run controls cannot be truncated silently.

## Evidence-panel verification and remaining work

All six panel accession pages were retrieved via NCBI's public series-text endpoint,
with exact response hashes, series titles and sample-record counts stored in panel
metadata. Their status is `series_metadata_verified`, replacing unsupported
`metadata_locked` claims. Roles/axis links remain candidate curation. Metadata does
not establish donor independence, phenotype direction, disease severity or model
performance. Public sources:

- https://www.ncbi.nlm.nih.gov/geo/query/acc.cgi?acc=GSE185289
- https://www.ncbi.nlm.nih.gov/geo/query/acc.cgi?acc=GSE240848
- https://www.ncbi.nlm.nih.gov/geo/query/acc.cgi?acc=GSE135310
- https://www.ncbi.nlm.nih.gov/geo/query/acc.cgi?acc=GSE153480
- https://www.ncbi.nlm.nih.gov/geo/query/acc.cgi?acc=GSE216211
- https://www.ncbi.nlm.nih.gov/geo/query/acc.cgi?acc=GSE269054

Next empirical work requires explicit subject/condition manifests, cell-type-aware
summaries, species/ortholog policy, reference-fit scaling, independently measured
phenotype labels, calibrated marker directions/ordinal thresholds and held-out
study/donor tests. These are unresolved; no dataset split or biological support
was guessed. The current runtime tests and real count fixture do not replace them.

## Local release checks

101 tests pass, including actual pinned stack adapters. Statement coverage is
94.12%; combined statement/branch coverage is 91.87%. Lint and formatting pass.
Source and wheel builds pass; an isolated wheel installation outside the checkout
successfully lists and materializes packaged scenarios, reads the evidence panel
and scores recovery. CI adds four Python versions, pinned stack tests and installed
wheel validation. Challenge-set version 1.1.0 records the relative-path/hash change.
The canonical CPU notebook is generated with an exact implementation commit;
older notebook names are explicitly archived rather than silently running stale
mutable-main validation code.
